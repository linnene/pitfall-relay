## 机制

- **共享内容**：每个 agent 的完整 on-policy 轨迹（观测、动作、奖励）。不是摘要、不是消息、不是失败。
- **使用阶段**：训练。执行期不发生任何共享。
- **执行期参数更新**：否。
- **发送方信息**：队友的轨迹本身。接收方对每条外来转移施加重要性采样比率 π_i(a|o;φ_i)/π_k(a|o;φ_k)，权重 λ=1，同时进入策略损失与价值损失。
- **接收方权限**：接收方保留自己的 actor/critic，不被替换成共享策略。
- **失败定义**：无。任务稀疏奖励，但失败未被单独建模。
- **记忆范围/遗忘/触发**：无跨局记忆；每个更新步都使用当批所有 agent 的轨迹。

## 学习目标

加权策略梯度，而非学习一个经验编码器。形式假设：一个 agent 的局部策略梯度对另一个 agent 是有用的学习方向；两 agent 推导还用到奖励独立与对称假设。

## 证据

- **泛化**：10 个稀疏奖励任务（Predator-Prey 3 agents、SMAC-3m、4 个 LBF、4 个 RWARE，2–4 agents），**无 held-out 任务/实例泛化实验**。
- **负迁移**：无专门分析。作者承认核心假设（跨 agent 梯度有用），并指出 λ 很小时退化为独立学习。观测到的重要性权重多在 0.5–1.5。
- **关键对照**：独立学习、参数共享、演示学习。
- **seed**：5 seeds，阴影为标准差；每 seed 取最优模型评 100 episodes。
- **算力**：未报告。
- **代码**：https://github.com/uoe-agents/seac（许可与提交本轮未核查）。

## 与本课题的关系

- **相同点**：明确回答"队友的经验能不能帮到我"。
- **关键差别**：共享的是原始转移且只在训练期；没有"经验表征"，没有"何时共享"，没有执行期使用，没有失败语义。
- **可能致命重叠**：中。如果 PitfallRelay 最终方案退化成"训练期让队友的经验进入我的更新"，会被视为 SEAC 的一个变体。
- **可复用**：重要性采样作为"来自不同策略的经验如何加权"的基线；λ 作为共享强度的连续旋钮，便于做同信息预算对照。
